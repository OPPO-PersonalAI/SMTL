# Data Workflow — Reasoning Trajectory Distillation Pipeline

## Overview

This module takes the QA pairs generated by `data_synthesis` and distills high-quality **search reasoning trajectories** from them, ultimately converting the trajectories into multi-turn dialogue format suitable for SFT training.

The entire pipeline consists of 4 steps and can be executed end-to-end with a single command:

```bash
INPUT_FILE=./data_workflow/input/your_qa_pairs.jsonl bash data_workflow/run_pipeline.sh
```

## Pipeline

```
QA Pairs (JSONL)
    │
    ▼
┌───────────────────────────────────────────────┐
│ Step 1: Generate Reasoning Trajectories       │
│   step1_run_parallelized_agent.py             │
│   - Launches a SearchAgent for each QA pair   │
│   - Agent autonomously searches, crawls, and  │
│     reasons via web_search + crawl_page tools │
│   - Output: results1/<stem>_traj.jsonl        │
└──────────────────┬────────────────────────────┘
                   │
                   ▼
┌───────────────────────────────────────────────┐
│ Step 2: Evaluate Trajectory Quality           │
│   step2_postprocess_eval_results.py           │
│   - Uses LLM to judge semantic consistency    │
│     between agent answers and ground truth    │
│   - Labels each trajectory: correct/incorrect │
│   - Output: results2/<stem>_evaluated.jsonl   │
└──────────────────┬────────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────────┐
│ Step 3: Filter Correct Trajectories          │
│   step3_postprocess_filter_defeat.py         │
│   - Keeps only trajectories with             │
│     judgement == "correct"                   │
│   - Output: results3/                        │
└──────────────────┬───────────────────────────┘
                   │
                   ▼
┌───────────────────────────────────────────────────┐
│ Step 4: Convert to Training Format                │
│   step4_postprocess_clean_and_transform_format.py │
│   - Cleans data, formats tool_call/response       │
│   - Converts to system/user/assistant             │
│     multi-turn conversations                      │
│   - Output: results_final/afm2_<date>_*.json      │
└───────────────────────────────────────────────────┘
```

## Prerequisites

### 1. Install Dependencies

```bash
pip install -r requirements.txt
```

### 2. Configure Environment Variables

Create a `.env` file in the project root (`SMTL-main/.env`) with the following variables:

```env
# LLM configuration (used for agent reasoning and answer evaluation)
DEFAULT_MODEL=deepseek-chat
OPENAI_API_KEY=your_api_key
OPENAI_API_BASE=https://api.deepseek.com

# Web search tool (supports multiple keys separated by | for rotation)
SERPER_API_KEY=your_serper_key
WEB_SEARCH_SERPER_API_KEY=your_serper_key

# Web crawling tool
JINA_API_KEY=your_jina_key
```

### 3. Prepare Input Data

The input file should be in JSONL format with at least the following two fields per line:

```json
{"question": "Which category has an expected growth rate of 2%...", "golden_answer": "U.S. Real GDP Growth Rate"}
```

- `question`: The question for the agent to answer.
- `golden_answer`: The ground-truth answer (used in Step 2 evaluation).

> **Note:** The input is typically produced by `data_synthesis` Step 8 (`step8_get_qa.py`), then sampled and simplified for this workflow.

## Usage

### One-Command Execution (Recommended)

```bash
INPUT_FILE=./data_workflow/input/your_qa_pairs.jsonl bash data_workflow/run_pipeline.sh
```

### Custom Parameters

```bash
INPUT_FILE=./data_workflow/input/your_qa_pairs.jsonl \
PARALLEL=20 \
MAX_STEPS=50 \
MAX_RETRIES=3 \
MAX_WORKERS=50 \
DATE_TAG=0309 \
bash data_workflow/run_pipeline.sh
```

### Configurable Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `INPUT_FILE` | *(required)* | Path to the input QA JSONL file |
| `SAMPLE_NUM` | all | Limit the number of samples to process |
| `PARALLEL` | 100 | Concurrency for Step 1 (trajectory generation) |
| `MAX_STEPS` | 50 | Maximum reasoning steps per agent run |
| `MAX_RETRIES` | 3 | Number of retries on API failures |
| `SUMMARY_INTERVAL` | 8 | Steps between agent summary generations |
| `PROMPTS_TYPE` | generation | Prompt template type (`default` / `generation` / `glm`) |
| `MAX_WORKERS` | 50 | Concurrency for Step 2 (evaluation) |
| `RESUME` | true | Whether Step 2 resumes from checkpoint |
| `DATE_TAG` | today | Date tag used in Step 4 output filenames |

## Output Directory Structure

```
data_workflow/
├── results1/          # Step 1: Raw reasoning trajectories
├── results2/          # Step 2: Evaluated trajectories (with correct/incorrect labels)
├── results3/          # Step 3: Filtered correct trajectories only
└── results_final/     # Step 4: Final training format (multi-turn dialogue JSON)
```

## Core Modules

### `FlashOAgents/`

The agent framework that powers Step 1:

- **`SearchAgent`** — Search-based agent using `web_search` + `crawl_page` tools.
- **`OpenAIServerModel`** — LLM interface compatible with OpenAI-style APIs.
- **`search_tools.py`** — `WebSearchTool` (Serper API) and `CrawlPageTool` (Jina API + LLM summarization).
- **`agents.py`** — `ToolCallingAgent` core reasoning loop with plan / summary / action / answer stages.
- **`prompts/`** — Prompt templates for different scenarios (`default`, `generation`, `glm`).

### `utils.py`

Common I/O utilities (`read_jsonl`, `write_jsonl`, `read_json`, `write_json`, etc.).
